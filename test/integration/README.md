# Сквозные тесты HPRPR-14

```sh
# По умолчанию infra берётся из соседнего клона ../infra; другой путь — через INFRA_DIR:
INFRA_DIR=../infra make test-integration   # по умолчанию
# Нагрузка: 40 посылок, клиентская конкуренция 8, worker: 1×1, 1×2, 2×1, 2×2, 4×1.
INFRA_DIR=../infra make test-load
# Более длинный или ограниченный прогон:
LOAD_N=100 LOAD_CONCURRENCY=8 LOAD_MATRIX='1:1 2:1' make test-load
```

Нужны Go версии из go.mod, Python 3, Docker Engine с cgroups/seccomp и Compose
с поддержкой `!override` (2.24.4+). Образы языков скачивает штатный worker.
Скрипт проверяет свободные 8080/8180/8333/9090, собирает текущий backend worktree,
поднимает **отдельный** проект `hprpr14-integration`, ждёт Keycloak и `/readyz`.
Postgres публикуется на случайном loopback-порту; 5432 хоста не используется.
Мониторинг не запускается. Нельзя одновременно запускать два таких стенда.
Скрипт откажется переиспользовать существующий проект.

Override дополняет `infra/compose.yaml`, сохраняя его realm, S3 и окружение backend.
`--env-file /dev/null` исключает неявное чтение `.env` оператора.
`BACKEND_CONTEXT` указывает именно на checkout/worktree, из которого вызван Make.
После успеха, ошибки или SIGINT/SIGTERM выполняется `down -v --remove-orphans`.
CI дополнительно делает cleanup через `if: always()`. После SIGKILL/остановки Docker
уборку нужно повторить вручную с теми же файлами и project name.

Тесты имеют тег `integration`. Запуск напрямую без `E2E_API_URL`,
`E2E_KEYCLOAK_URL`, `E2E_DATABASE_URL` заканчивается ошибкой, а не skip.
REST-клиент использует сетевой grpc-gateway и выключенный keep-alive;
S3 PUT идёт по неизменённой подписанной ссылке, решения исполняет реальный worker/Docker.

В каждом тесте проверяется вход стандартных `student/author/admin@autocheck.local`
с паролем по роли через `autocheck-cli`. Для независимых квот и приватности создаются
дополнительные уникальные студенты через admin API **одноразового** Keycloak
(`master`, `admin-cli`, локальный admin/admin). Их рабочие токены также выдаёт
`autocheck-cli`. У каждого сценария свои UUID, slug, задания и данные;
порядок запуска не влияет на результат, параллельного изменения общих квот нет.
Все учётные записи, SQL-фикстуры и S3-объекты исчезают вместе с volumes стенда.

Pro выдаётся SQL-фикстурой `driver.Pro` через отдельное подключение к тестовой БД.
Месячная квота проверяется на штатном тарифе free: тест записывает 100 исторических
результатов и проверяет через REST расход 100, остаток 0, отказ 429 и успешный
реальный прогон после Pro. Тарифы/продовый API не меняются. Лимит компиляций
достигается настоящими REST-посылками, без SQL-фикстуры расхода.

Покрыты 23 сочетания языка/вердикта: все шесть для Go/C++/Java, для Python —
OK/WA/TL/ML/RE (отдельной компиляции у него нет). Каждый watch должен дойти до DONE;
FAILED/SE, streaming error и преждевременный EOF считаются ошибкой. Для WA проверяются
вход/эталон/вывод/diff открытого теста и отсутствие этих полей у закрытого.
Дополнительно: чужие посылки/source/report/watch/hints, черновики заданий,
feedback и смена статуса только admin, идемпотентность, free/Pro материалы,
playground stdout и права, генерация → запуск эталона → accept, embeddings-подбор
и подсказка с повтором.

LLM **всегда** направлен на отдельный `llmstub:8099/v1`; ключ, модели и URL
переопределены для api/worker/migrate. Заглушка не имеет внешнего клиента:
отвечает фиксированными входами и русскими текстами, возвращает эмбеддинги
по одному на вход, неизвестные маршруты/инструкции отвергает. Проверяются точные
ответы заглушки и отсутствие текстового fallback подбора. OpenRouter не вызывается,
даже если ключ есть в окружении оператора.

ЮKassa по умолчанию выключена: тест проверяет `checkoutEnabled=false` и HTTP 503
с публичным сообщением. Для проверки создания checkout явно передайте
`YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` **тестового** магазина через окружение.
Тогда проверяются payment/confirmation URL и повтор по request_id;
подтверждение/списание оплаты не выполняется. Ключи и токены не выводятся.

В CI `.github/workflows/integration.yml` автоматически работает на PR/main
и вручную через workflow_dispatch: отдельный checkout infra, сборка backend из PR,
тот же `make test-integration`, без секретов магазина/LLM. Требуется публичный доступ
к autocheck-team/infra. Сетевые сбои registry и нехватка ресурсов приводят к ошибке,
не маскируются под skip. Локальный запуск проверен; результат GitHub job нужно
проверить после публикации изменений.

Нагрузочный драйвер и фактические измерения: [docs/load-testing.md](../../docs/load-testing.md).
